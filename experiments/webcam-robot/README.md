# 웹캠 정지 이미지 · 부위별 로봇 표현 실험

관련 이슈: [#11](https://github.com/team-injeolmi-jaegyueo/2027-graduation-exhibition/issues/11) · 담당: 정규호 (@kokkumong) · 목표일: 2026-10-26

## 검증할 질문

촬영 이미지의 관절 좌표와 부위별 0–100 값을 Three.js 임시 로봇 표현에 연결할 수 있는가? 원본 사진 위에 로봇 기하 모델을 겹치는 실험으로, 원래 신체를 제거하거나 자연스럽게 대체하는 합성은 아니다. 비율은 불투명도에 대응한다. 질문 가중치·관객 UI·최종 모델은 후속 작업이다.

## 환경 / 실행

- macOS, Node 22.23.3 / npm 10.9.9（설치 실행 환경 npm 11.12.1）
- MediaPipe Tasks Vision 1.1.0 / Three.js 0.186.1 / Vite 8.3.4 (잠금 파일 포함)
- WebGL2 및 카메라 지원 브라우저. 카메라는 localhost 또는 HTTPS 필요.
- 웹캠 모델·브라우저 버전·실제 해상도는 장비 테스트 때 기록한다.

이 폴더에서:

```sh
npm ci
npm run dev
```

터미널의 localhost URL을 연다. postinstall이 패키지 WASM을 public/wasm에 복사한다. 첫 실제 촬영 시 Google 공식 Pose Landmarker lite 모델(float16 / version 1)을 다운로드하므로 인터넷 연결이 필요하다. 사진·좌표는 서버에 전송하거나 디스크·localStorage에 저장하지 않는다. 초기화·탭 종료 시 세션 데이터와 카메라 사용을 정리한다. 모델 로컬 배포와 오프라인 검증은 후속 작업이다.

```sh
npm test
npm run build
```

## 사용법

1. 데모 좌표 테스트: 직접 생성한 실루엣과 고정 관절 좌표로 3D 배치·비율 조절 확인. 자동 인식 성공을 의미하지 않는다.
   인식 모델 점검 버튼은 모델 다운로드·WASM 초기화·빈 이미지 인식을 실행한다. 카메라 없이 실행 가능하며 사람 인식 품질을 검증하지는 않는다.
2. 카메라 연결: 브라우저·macOS 권한을 허용하고 전신이 보이도록 거리를 확보한다.
3. 정지 이미지 촬영: 원본 이미지를 한 번 인식한 뒤 카메라를 끈다. 검출 부위와 관절을 확인한다.
4. 부위 슬라이더와 전체 0% / 100%로 표현 확인. 미검출 부위는 비활성화된다.
5. 다시 연결해 재촬영하거나 초기화로 이미지·좌표·비율 삭제.

측정값은 촬영 복사 / 인식 실행 / CPU 측 렌더 제출 시간이다. 모델 다운로드와 GPU 프레임 완료 시간은 포함하지 않는다.

## 입력·출력 계약 (실험 v0)

- 입력: 원본 방향 canvas, 너비·높이, MediaPipe 관절 33개, 부위별 0–100 수치.
- 원본 이미지 왼쪽 위가 (0,0), x/y는 0–1. 화면 표시에서만 x를 반전한다. 미리보기·사진·관절·3D 모두 동일한 거울 방향이다.
- 좌우 부위명은 관객 기준이다. 화면 반전 시 관절 인덱스를 바꾸지 않는다.
- visibleParts는 필요한 관절 모두 화면 안에 있고 visibility ≥ 0.6, presence ≥ 0.6일 때만 부위를 반환한다.
- torso / leftArm / rightArm / leftLeg / rightLeg. 머리·얼굴·손·발 세부 표현은 미포함.
- 관절 사이에 박스 메시를 배치한다. 몸통은 어깨·골반 중심으로 배치한다. 이미지 좌표 기반 정면 정합이며 실제 깊이·가림 처리는 하지 않는다.

## 검증 기록

| 항목 | 결과 |
| --- | --- |
| 좌표 반전·미검출·화면 밖 관절 단위 검사 | 3개 통과 |
| 프로덕션 빌드 | 통과, Three.js 포함 500kB 초과 청크 경고 있음 |
| 데모 3D 표시·개별 부위·0/100%·초기화 | Codex 인앱 브라우저에서 통과 |
| 모델 다운로드·WASM·빈 이미지 인식 | 통과, 빈 이미지에서 0명 검출 |
| 실제 웹캠 촬영·인식·재촬영 | 미검증 |
| 권한 거부·장치 미연결·연결 요청 중 초기화 | 미검증 |
| 부분 검출·모델 네트워크 실패 | 미검증 |

2026-10-13: 인앱 브라우저의 카메라 연결은 권한 응답 대기 상태까지 확인했다. 실제 웹캠 성공·권한 거부를 통과로 기록하지 않는다. 브라우저·OS 권한을 사용자 환경에서 허용한 뒤 테스트를 이어간다. 데모 렌더 제출은 초기 셰이더 준비 후 약 0.1–0.6ms였으며 장비 목표 성능을 보장하는 수치는 아니다.

실제 장비에서 정상 촬영 10회, 어두운 환경·팔 가림·상반신 조건, 권한 거부, 재촬영, 카메라 연결 요청 중 초기화, 모델 다운로드 실패를 확인한다. 장비/OS/브라우저/해상도/시간/검출 부위/실패 원인을 기록하며 관객 사진은 커밋하지 않는다. 하드웨어 검증이 끝날 때까지 이슈는 열어둔다.

## 한계와 다음 결정

- Maya → Unity → Three.js 에셋 전달 검증은 별도 필요하다. Unity 프로젝트를 바로 Three.js에 배포하는 기능은 구현하지 않았다.
- 최종 모델의 GLB/glTF 내보내기, 축·단위·부위명·리깅·재질을 확인한 뒤 임시 박스 표현을 교체한다.
- 어깨부터 손목, 골반부터 발목이 모두 보여야 해당 팔다리를 표시한다. 부스 촬영 거리와 전신/상반신 범위를 결정해야 한다.
- 원본 신체 제거·부위 마스크·얼굴 매칭·가림 처리 미구현. 현재 결과로 자연스러운 변환을 검증했다고 판단하지 않는다.
- 인식은 메인 스레드에서 실행한다. 실장비의 멈춤 시간을 측정해 Worker 전환 여부를 결정한다.
