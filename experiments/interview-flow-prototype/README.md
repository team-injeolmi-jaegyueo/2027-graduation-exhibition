# interview-flow-prototype

Figma 시안을 기반으로 만든 면접 체험 흐름 웹 프로토타입입니다. 통합 앱(`app/`)의 프레임워크를 정하기 전에 화면 흐름·전환 인터랙션과 웹캠 정지 이미지 촬영 UX를 확인하기 위한 실험입니다.

## 1. 연결된 이슈와 검증할 질문

- 이슈: #13 `[TASK] 면접 흐름 웹 프로토타입 실험 추가`
- 관련 실험: #11 웹캠 정지 이미지와 부위별 로봇 표현 연동 (`experiments/webcam-robot/`)

검증할 질문

1. Figma 시안의 화면들이 하나의 관객 흐름으로 자연스럽게 이어지는가?
2. 웹캠 정지 이미지 촬영(카운트다운 → 셔터 → 확정)을 전시 관객이 안내 없이 진행할 수 있는가?
3. 섹션(가치관·직무적합성·인성)과 질문·선택 구조를 데이터로 분리해 확장할 수 있는가?

성공 기준

- 홈부터 면접 완료까지 끊김 없이 진행되고 스크립트 오류가 없다.
- 카메라 권한 허용 시 실제 촬영, 거부·미연결 시 대체 화면으로 흐름이 이어진다.
- 질문·섹션 문구를 HTML 수정 없이 스크립트의 데이터 배열에서 바꿀 수 있다.

## 2. 환경

- 단일 `index.html` (HTML·CSS·JavaScript, 빌드·의존성 없음)
- 외부 CDN: Pretendard(jsDelivr), Saira·Noto Sans KR(Google Fonts)
- 확인 환경: macOS, Chrome. 1920×1080 무대를 화면 크기에 맞춰 축소·확대합니다.

## 3. 설치 및 실행

```bash
cd experiments/interview-flow-prototype
python3 -m http.server 8137
# 브라우저에서 http://localhost:8137 접속
```

- 웹캠은 `localhost` 또는 https에서만 동작합니다. `file://`로 열면 카메라를 쓸 수 없습니다.
- **넥슨 폰트(선택)**: 라이선스 확인 전이라 저장소에 포함하지 않았습니다. 시안과 같은 글꼴로 보려면 [넥슨 폰트](https://brand.nexon.com/brand/fonts)에서 받아 이 폴더의 `fonts/`에 아래 이름으로 넣습니다. 없으면 Pretendard로 대체되어 표시됩니다. (`fonts/`는 `.gitignore`로 제외)
  - `fonts/NEXONFootballGothicB.otf` — 팝업 제목
  - `fonts/NEXONLv2GothicMedium.otf`, `fonts/NEXONLv2GothicBold.otf` — 팝업 본문·질문 화면

## 4. 화면 흐름

1. 홈 — 아래로 스크롤/스와이프(또는 하단 화살표)
2. 면접대기실 — 면접 도우미 로봇 등장, 대화창 3줄(클릭·Enter·스크롤로 넘김)
3. 직무 선택 — 6개 직무, 선택 시 패널이 옆으로 이동하고 직무 캐릭터 등장, 직무 설명 표시
4. 선택하기 → 면접진행안내 팝업(평가 영역 칩 호버 시 설명)
5. 확인 → 사진촬영안내 → 촬영하기: 팝업 안쪽이 촬영 영역, 바깥은 어둡게
6. 셔터 → 3·2·1 → 촬영 확정 → 사진이 지원자 배지로 이동
7. SECTION 01 가치관 → 질문 1 → SECTION 02 직무적합성 → 질문 1 → SECTION 03 인성 → 질문 1
8. 면접 완료 → 처음으로

좌하단 **DEV** 버튼으로 각 단계에 바로 이동할 수 있습니다.

데이터 위치 (`index.html` 스크립트)

- `DIALOG` 면접대기실 대사, `JOBS` 직무·캐릭터·설명
- `SECTIONS` 섹션 안내 문구·카드, `QUESTIONS` 섹션별 질문·선택지·제한 시간
- `DEV_STEPS` DEV 메뉴 단계

## 5. 테스트 자료와 출처

- 배경·캐릭터·UI 이미지: 팀 Figma 시안에서 내보낸 팀 제작 자료
- 면접 도우미 로봇 애니메이션 `img/robot.gif`: 팀 제작
- 관객 사진: 저장하지 않습니다. 촬영 이미지는 세션 메모리에서만 사용하고 새로고침·처음으로 시 사라집니다.

## 6. 결과

- 2026-10-27, macOS + Chrome 계열 브라우저: DEV 메뉴 14단계 이동과 질문 선택→다음→섹션 전환→면접 완료 흐름이 동작합니다.
- 넥슨 폰트를 넣지 않은 상태에서는 폰트 파일 404가 콘솔에 3건 표시되고 Pretendard로 대체됩니다. 폰트를 넣으면 콘솔 오류가 없습니다.
- 카메라 권한 거부·미연결 시 "카메라 연결 없음" 대체 화면으로 촬영 단계를 마칠 수 있습니다.
- **미검증**: 실제 웹캠으로 촬영 → 사진이 지원자 배지로 이동하는 경로는 아직 확인하지 않았습니다(개발 미리보기 환경에서 카메라가 차단됨). Chrome에서 권한 허용 후 확인이 필요합니다.
- 미리보기 배포: https://passprototype-roan.vercel.app (개인 Vercel, 이 폴더와 같은 내용)

## 7. 한계와 다음 작업

- 질문은 섹션당 1개의 임시 문항입니다. 문항·선택지 수(안내 카드의 "5지 선다"와 실제 3개)를 기획에서 확정해야 합니다.
- 답변은 `answer`·`interviewend` 이벤트로만 내보내며 로봇화 가중치·최종 판정과 연결되지 않았습니다.
- 촬영 이미지는 `photocaptured` 이벤트로 전달됩니다. #11의 부위 인식·로봇 표현과 연결할 입력 형식을 정해야 합니다.
- `img/robot.gif`가 약 21MB입니다. 전시 PC 로딩 시간을 확인하고 WebM 등 경량 형식 전환을 검토합니다.
- 단일 파일 구조라 통합 앱으로 옮길 때 화면·상태·데이터 모듈로 분리가 필요합니다.
