# app

관객이 사용하는 통합 프로그램을 두는 폴더입니다.

촬영, 질문·답변, 로봇화 상태, 결과 표시, 초기화 흐름을 연결합니다. 웹캠 인식과 로봇 표현은 각각 모듈로 구분하고 서로의 내부 구현 대신 명시적인 입력·출력으로 연결합니다.

화면을 여러 개 사용하더라도 동일한 관객 세션 상태를 기준으로 동작하도록 설계합니다.

## 현재 상태

Figma 시안 기반의 **면접 흐름 웹 프로토타입**(단일 `index.html`)을 통합 프로그램의 출발점으로 둡니다. 프레임워크는 아직 정하지 않았으며, 빌드·의존성 없이 정적 파일로 실행합니다. 프레임워크를 정하면 화면·상태·데이터 모듈로 나누고 설치·실행·검증 명령을 갱신합니다.

- 관련 이슈: #13
- 관련 실험: #11 웹캠 정지 이미지와 부위별 로봇 표현 연동 (`experiments/webcam-robot/`)

## 실행

```bash
cd app
python3 -m http.server 8137
# 브라우저에서 http://localhost:8137 접속
```

- 웹캠은 `localhost` 또는 https에서만 동작합니다. `file://`로 열면 카메라를 쓸 수 없습니다.
- 외부 CDN: Pretendard(jsDelivr), Saira·Noto Sans KR(Google Fonts)
- **넥슨 폰트(선택)**: 라이선스 확인 전이라 저장소에 포함하지 않았습니다. 시안과 같은 글꼴로 보려면 [넥슨 폰트](https://brand.nexon.com/brand/fonts)에서 받아 `app/fonts/`에 아래 이름으로 넣습니다. 없으면 Pretendard로 대체되며 콘솔에 폰트 404가 표시됩니다. (`fonts/`는 `.gitignore`로 제외)
  - `fonts/NEXONFootballGothicB.otf` — 팝업 제목
  - `fonts/NEXONLv2GothicMedium.otf`, `fonts/NEXONLv2GothicBold.otf` — 팝업 본문·질문 화면

## 화면 흐름

1. 홈 — 아래로 스크롤/스와이프(또는 하단 화살표)
2. 면접대기실 — 면접 도우미 로봇 등장, 대화창 3줄(클릭·Enter·스크롤로 넘김)
3. 직무 선택 — 6개 직무, 선택 시 패널 이동·직무 캐릭터 등장·직무 설명 표시
4. 선택하기 → 면접진행안내 팝업(평가 영역 칩 호버 시 설명)
5. 확인 → 사진촬영안내 → 촬영하기: 팝업 안쪽이 촬영 영역, 바깥은 어둡게
6. 셔터 → 3·2·1 → 촬영 확정 → 사진이 지원자 배지로 이동
7. SECTION 01 가치관 → 질문 → SECTION 02 직무적합성 → 질문 → SECTION 03 인성 → 질문
8. 면접 완료 → 처음으로

좌하단 **DEV** 버튼으로 각 단계에 바로 이동할 수 있습니다.

## 데이터와 출력

`index.html` 스크립트에서 관리합니다.

| 이름 | 내용 |
| --- | --- |
| `DIALOG` | 면접대기실 대사 |
| `JOBS` | 직무·캐릭터 이미지·설명·과제전형 안내 |
| `SECTIONS` | 섹션 안내 문구·진행 방식 카드 |
| `QUESTIONS` | 섹션별 질문·선택지·제한 시간 |
| `DEV_STEPS` | DEV 메뉴 단계 |

다른 모듈과의 연결 지점은 `#stage` 요소에서 발생하는 이벤트입니다. 입력·출력 형식은 확정 전입니다.

| 이벤트 | detail |
| --- | --- |
| `jobconfirm` | 선택한 직무 id |
| `photocaptured` | 촬영 이미지 data URL (세션 메모리에서만 사용) |
| `answer` | `{ section, choice }` |
| `interviewend` | 섹션별 선택 결과 |
