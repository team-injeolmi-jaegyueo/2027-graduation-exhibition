# 프로젝트 구조와 통합 원칙

## 현재 범위

웹캠 정지 이미지 촬영, 신체 부위 인식, 답변에 따른 부위별 로봇 변환, 면접 진행과 최종 판정이 하나의 체험을 구성합니다. 연속적인 실시간 매칭은 초기 범위에 포함하지 않습니다.

## 책임 구분

| 위치 / 모듈 | 책임 |
| --- | --- |
| experiments | 촬영·인식·합성 방식의 가능성 검증 |
| app의 촬영·인식 모듈 | 촬영 이미지 및 부위 인식 결과 제공 |
| app의 면접·상태 모듈 | 질문, 답변, 로봇화 가중치와 체험 단계 관리 |
| app의 로봇 표현 모듈 | 이미지·인식 결과·로봇화 상태에 따른 표현 |
| app의 결과·초기화 흐름 | 최종 판정 표시와 다음 관객을 위한 초기화 |
| assets | 실행에 사용하는 모델·이미지·사운드 |
| docs | 인터페이스, 실행 방법, 작업계획과 기술 결정 |

이는 책임 구분이며 아직 실제 소스 경로나 인터페이스를 확정한 것은 아닙니다. 초기 실험이 끝난 뒤 입력·출력 형식을 정합니다.

## 통합 시 확인할 사항

- 촬영 이미지의 크기·방향·좌표 기준과 인식 실패 표현
- 신체 부위 이름과 로봇화 비율의 단위·범위
- 질문 데이터와 가중치의 버전 및 판정 기준
- 카메라 권한 거부·촬영 실패·부위 미검출 시 관객 안내와 대체 흐름
- 세션 종료·초기화 시 이미지와 상태의 처리

촬영 이미지와 인식 결과는 기본적으로 세션 내에서 처리합니다. 디버깅용 저장이 필요하면 공유 가능한 테스트 자료만 사용합니다.

## 미결정 사항

- 인식 라이브러리와 합성 방식
- 웹 앱 프레임워크와 실행·배포 환경
- Maya·Unity 제작 결과의 웹용 내보내기 경로
- 화면 간 동기화와 장치 연결 방식

구조 정리 단계에서 위 선택을 확정하지 않습니다. 실험 결과를 근거로 필요한 폴더와 도구만 추가합니다.
